# Traccar для intraHouse

Плагин читает последнюю известную позицию трекера через REST API Traccar. Подходит для Teltonika и других трекеров, подключённых к Traccar. Один экземпляр поддерживает до трёх трекеров на одном сервере.

## Установка

1. На GitHub нажмите **Code → Download ZIP** или [скачайте ZIP исходников](https://github.com/apnagaev/intrahouse-traccar-plugin/archive/refs/heads/main.zip).
2. В панели сервера intraHouse откройте **Плагины → Import**, выберите ZIP и обновите Project Manager. Файлы `traccar.ih`, `manifest.json`, `index.js` и каталог `v5` находятся в корне исходников. Плагин использует Node.js 18+ и встроенный fetch.
3. Добавьте экземпляр Traccar. Введите базовый URL веб-сервера Traccar (например, `https://traccar.example.org`), токен аккаунта с доступом к трекеру, числовой `deviceId` из Traccar и интервал опроса. По умолчанию 30 секунд, диапазон 10–600. При необходимости заполните `deviceId2` и `deviceId3`.
4. В контекстном меню экземпляра добавьте **Набор каналов Traccar**, привяжите нужные каналы к свойствам устройства и запустите экземпляр.

Плагин использует `GET /api/positions`, который возвращает последние позиции устройств, доступных аккаунту. Экземпляр публикует позиции настроенных трекеров. Используйте HTTPS для передачи токена. В GitSync маскируйте поле `token`, если конфигурация проекта хранится в Git.

## Каналы для Polo

| Канал | Значение |
| --- | --- |
| `online`, `has_position`, `valid` | Доступность API, наличие позиции выбранного трекера и признак валидности от Traccar |
| `fix_time`, `server_time` | Unix-время в секундах. Для сравнения свежести Pandora и Teltonika используйте `fix_time` |
| `latitude`, `longitude`, `address` | Координаты и адрес позиции |
| `geofence_ids`, `geofence_id` | JSON-список зон и первая зона. Подтверждённый пустой список публикуется как `[]` и `0` |
| `power`, `ignition`, `motion` | Питание, зажигание и движение из атрибутов позиции |
| `speed`, `obd_speed` | GPS-скорость в км/ч после пересчёта из узлов и исходное значение Traccar `obdSpeed` |
| `attributes` | Исходные атрибуты Teltonika и других протоколов в JSON |

При ошибке связи плагин публикует `online=0` и `has_position=0`, сохраняя последние полученные показания. Отсутствующие в позиции атрибуты не заменяются нулями. Для автоматизаций проверяйте доступность, валидность и возраст позиции. Правила выбора источника, геозон и Shelly задаются сценариями проекта.

## GitSync

Если отправка сообщает об отсутствии `UNIT_TRACCAR1_TOKEN` в `.env`, сохраните токен в параметрах intraHouse и выполните на сервере:

```sh
cd /var/lib/intrahouse/projects/lav24 &&
python3 /var/lib/intrahouse/plugins/gitsync/ops/ihsecrets.py extract &&
python3 /var/lib/intrahouse/plugins/gitsync/ops/ihsecrets.py check
```

При нуле утечек повторите отправку через Git проекта. Если `extract` пишет «ничего нового», а ошибка об отсутствующей переменной сохраняется, сохраните токен заново и повторите команды. GitSync маскирует поле `token` в Git и подставляет сохранённое значение из локального `.env` при восстановлении.

## Источник координат

Основной трекер сохраняет прежние имена каналов, дополнительные используют префиксы `tracker2_` и `tracker3_`. Автоматический выбор идёт в порядке настройки ID. Точка должна быть валидной и не старше пяти минут по времени фиксации и приёма. Фильтр отбрасывает скачки относительно последней принятой точки и скорость выше 200 км/ч. При отсутствии подходящей точки `source_ready=0`; координаты и адрес в автоматизациях используйте только при `source_ready=1`. Для геозон дополнительно проверяйте `source_geofence_known`.

Запись в `set_source_mode` переключает источник: 0 — автоматически, 1–3 — вручную. Ручной режим использует те же проверки качества и действует до перезапуска. Поле `sourceMode` задаёт начальный режим. Для Teltonika, Pandora и магнитолы рекомендуемый порядок в этом авто: 168, 481, 1169.
